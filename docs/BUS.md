# اتوبوس: وضعیت و برنامه (۱۴۰۵/۰۸/۰۱)

## منبع داده (نسخه‌ی اول، پیش‌فرض)
- مسیر و ایستگاه‌ها: OSM، relation با `route=bus` در محدوده‌ی مشهد.
- سرفاصله: در OSM نیست. تا برداشت میدانی یا فید شهرداری، `headway_min = null` و کیفیت `unknown` است. هیچ عددی حدس زده نمی‌شود.
- فید GTFS یا API رسمی اتوبوسرانی مشهد پیدا نشد.

## اجرا روی VPS (Overpass از این سندباکس بسته است)
```
curl -sS -G https://overpass-api.de/api/interpreter --data-urlencode "data@scripts/overpass/bus_mashhad.overpassql" -o data/bus/osm/bus_mashhad.json
cd packages/core && npm run osm:bus
```
خروجی: `data/bus/lines.json`. رابطه‌هایی که کمتر از ۲ ایستگاه قابل‌استفاده دارند در `dropped` با دلیل ثبت می‌شوند.

## اعتبارسنجی لازم (قبل از استفاده)
- تعداد خط‌ها و نام‌ها در برابر وب‌سایت شهرداری یا تابلوی ایستگاه.
- ایستگاه‌های تکراری (دو جهت یک خط) و ایستگاه‌های بدون نام.
- هر خط باید حداقل یک برداشت سرفاصله‌ی میدانی داشته باشد تا از `unknown` به `field` برود.

## مسیریاب (موقتاً کنار گذاشته شد)
- موتور پیاده و خودرو هنوز انتخاب نشده است (تصمیم کاربر).
- مستندات نشان قابل خواندن نبود (robots). از نتایج جست‌وجو: مسیریابی با ترافیک زنده، ماتریس فاصله، TSP، ایزوکرون. حمل‌ونقل عمومی را ندیدم.

## قدم بعدی پیشنهادی
۱. اجرای Overpass روی VPS و تولید `data/bus/lines.json`.
۲. انتخاب ۳ خط شلوغ برای برداشت سرفاصله‌ی میدانی.
۳. وقتی مسیریاب انتخاب شد: گراف مشترک مترو + پیاده + اتوبوس با RAPTOR.
