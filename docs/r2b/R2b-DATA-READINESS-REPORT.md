# R2b — Data Readiness & Corridor Selection Report

**تاریخ:** ۲۰۲۶-۱۱-۰۲

**نتیجه Gate: BLOCKED — هیچ کریدور دارای زنجیره کامل شواهد A→B در داده موجود تأیید نشد.**

**اقدام:** مرحله Data Readiness انجام شد و مطابق شرط مالک، پیش از پیاده سازی Limited A-to-B Planner متوقف شدیم. این گزارش، تکمیل Planner یا اجرای سفر میدانی را ادعا نمی کند.

## ۱. خلاصه تصمیم

پروژه برای سفر مدل شده **سکو به سکو روی یک خط** پایه قابل استفاده دارد: R1 و R2a، هویت ایستگاه ها، ترتیب توقف، مدل زمان بندی و ثبت های حرکت قطار موجودند. اما زنجیره زیر برای هیچ محدوده بررسی شده به صورت قابل ردیابی تأیید نشد:

```text
A واقعی → مسیر پیاده قابل پیمایش → ورودی معتبر
→ سکوی جهت درست → سفر مترو
→ خروج از سکوی مقصد → خروجی معتبر → مسیر پیاده → B واقعی
```

شکاف های مسدود کننده:

- نگاشت معتبر ورودی/خروجی به ایستگاه و سکوی جهت درست؛
- هندسه و اتصال پیوسته approach/egress با قیود عبور؛
- مسیر و مدل زمانی دسترسی داخلی ایستگاه؛
- روش زمانی منبع دار برای تمام قطعات پیاده و مرز روشن A/B.

**نبود کرایه، دلیل اصلی بسته بودن Gate نیست.** پایلوت صرفاً زمان محور می تواند بعداً با هزینه unknown اجرا شود؛ اما زمان و اتصال قطعات لازم را نمی توان با صفر یا حدس تکمیل کرد.

هیچ Planner، مسیر مصنوعی، ETA از فاصله مستقیم، ورودی حدسی، انتقال صفر در شریعتی یا کارت A→B نمایشی ساخته نشد. اجرای R2a با نام جدید و افزودن صفر برای دسترسی، پایلوت واقعی نیست.

فایل با نام پنجشنبه، ۱۴ ردیف خط ۲ جمعه را هم در ابتدا تکرار می کند. نام فایل یا کپی ردیف، مشاهده مستقل جدید یا اندازه گیری پنجشنبه ایجاد نمی کند. raw data و ledger اصلاحات موجود دست نخورده ماندند.

## ۵. ماتریس آمادگی اجزای مسیر

این وضعیت برای محدوده های پیشنهادی برداشت صدق می کند، مگر تفاوت های بخش بعد:

- **مختصات و هویت:** موجود و قابل استفاده به عنوان registry؛ ورودی/خروجی یا دقت دسترسی تأیید نشده است.
- **ورودی/خروجی معتبر:** نگاشت لازم موجود نیست؛ blocker الزامی.
- **هندسه پیاده قابل پیمایش:** قطعات پراکنده داریم، زنجیره کامل approach/egress نداریم؛ blocker الزامی.
- **زمان پیاده و روش:** مدل منبع دار یا observation مربوط به این قطعات تأیید نشد؛ blocker الزامی.
- **قیود عبور/دسترسی:** بعضی tag ها موجودند، ولی پوشش و تطبیق کریدوری/داخلی کامل نیست؛ عبور آزاد فرض نمی شود.
- **زمان بندی مترو:** از R2a قابل بازاستفاده، modeled/estimated و مشروط به سیاست روز خدمت؛ شاهد بخش مترو است، نه دسترسی از خیابان.
- **انتقال:** در گزینه های تک خط لازم نیست؛ برای شریعتی مسیر و زمان انتقال تأیید نشده است.
- **تعرفه:** مبلغ، نوع بلیت، تاریخ اعتبار و قاعده هزینه نهایی تأیید نشده؛ unknown و اختیاری برای پایلوت زمان محور.
- **تقویم/عدم قطعیت:** تقویم جامع تعطیلات نداریم؛ سیاست strict یا baseline صریح R2a باید حفظ شود. تشخیص جمعه، تأیید عملیات واقعی نیست.

پس Gate به دلیل شکست زنجیره دسترسی بسته است، نه صرفاً به دلیل مجهول بودن قیمت یا نداشتن سرویس زنده.

## ۹. وضعیت معماری و اتصال R1/R2a

هیچ الگوریتم A→B پیاده سازی نشده است. برنامه بعد از عبور Gate، حفظ Modular Monolith و ترکیب محدود مسیرهای معتبر پیاده با خروجی R2a است؛ نیازی به انتخاب الگوریتم مشهور یا زیرساخت تازه پیش از شناخت اندازه مسئله نیست.

حسابداری زمانی آینده باید روشن باشد: دسترسی تا سکو، زمان `readyAt` R2a را می سازد؛ duration خروجی R2a خودش انتظار و حرکت را دارد؛ egress پس از arrival اضافه می شود. شروع نهایی از ساعت واقعی A است، نه ساعت سکو. انتظار دو بار اضافه نمی شود و قطعه ورود/خروج حذف نمی شود.

Constraints کل سفر باید پس از ساخت Candidate کامل A→B در R1 اعمال شوند. فرستادن حد duration کل سفر به R2a به تنهایی کافی نیست. Preferenceهای صریح باید در تصمیم سطح A→B و با objectiveهای سازگار اعمال شوند؛ R2a فعلی خودبه خود این ترکیب را انجام نمی دهد.

این موارد طراحی آینده اند، نه قابلیت تازه فعال. هیچ Memory کاربر ثبت نشده است.

## ۱۰. آزمون، کارایی و کیفیت ETA

برای حفظ خط مبنا، وابستگی های lockfile موجود در worktree مستقل به صورت offline و با lifecycle script غیرفعال نصب شدند؛ dependency declaration یا lockfile جدیدی ایجاد نشد.

مجموعه موجود دوباره و سری اجرا شد:

- Core: **۳۷۴** تست موفق.
- Mini App / data / n8n: **۱۹۸** تست موفق.
- Release Inventory: **۱۲** تست موفق.
- Bus Catalogue Python: **۱۷** تست موفق.
- جمع: **۶۰۱ موفق، صفر شکست**؛ typecheck، build موجود و bus `--check` نیز exit code صفر داشتند.

**تست الگوریتم R2b جدید: صفر، چون الگوریتمی ساخته نشده است.** پاس شدن تست های قبلی، دسترسی پیاده، اعتبار هندسه یا ETA A→B را تأیید نمی کند. هیچ assertion قدیمی ضعیف نشده و source محصول نسبت به R2a بدون تغییر است.

Benchmark و بودجه latency جدید A→B اعلام نمی شود: هنوز graph/گزینه واقعی برای اندازه گیری نداریم. نتایج R2a، تضمین مصرف حافظه یا Event Loop Planner مرکب نیستند. بعد از تأمین داده، همان سقف ۱۹۲ MiB، cache، concurrency، افق و تعداد گزینه ها باید روی بار واقعی اندازه گیری شوند؛ قبل از آن HTTP عمومی مجاز نیست.

دقت الگوریتم با دقت داده و ETA میدانی جدا است. هیچ سفر مستقل A→B برای ارزیابی دقت در این مرحله انجام نشده و هیچ درصد دقت یا خطای رسیدن واقعی اعلام نشده است.
