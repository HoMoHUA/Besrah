# آزمون User-Agent نشان و دسترسی نقشه شهرداری مشهد

تاریخ: ۳۰ اکتبر ۲۰۲۶. بررسی فقط خواندنی بود؛ رابط، زمان بندی و سرویس های بِسراه تغییر نکردند.

## نتیجه اجرایی

**نسخه وب نشان هم می تواند برای این ایستگاه عدد نمایش دهد. در این آزمایش، هدر اختصاصی اپ برای نمایش عدد لازم نبود؛ اما API مستقیم قابل استفاده در محصول و تازگی خود خوراک هنوز تایید نشده اند.**

سه درخواست محدود به مسیر مشاهده شده `passing-lines`، با هدر مرورگر دسکتاپ، مرورگر اندروید و رشته آزمایشی `Neshan`، HTTP 200 گرفتند. هیچ کلید، توکن یا کوکی ارسال نشد. بدنه هیچ کدام با تجزیه معمول JSON خوانده نشد. رشته `Neshan` صرفاً آزمایشی است؛ **User-Agent واقعی اپ شناسایی و تایید نشده است**. نتیجه این آزمون به همه API های احتمالی اپ تعمیم داده نمی شود.

هدر `User-Agent` معرف نرم افزار درخواست کننده است؛ جایگزین احراز هویت نیست. اگر یک مسیر به احراز هویت نیاز داشته باشد، تغییر نام نرم افزار آن نیاز را برطرف نمی کند. نیاز واقعی API بومی اپ به کلید یا امضا در این بررسی مشخص نشده است.[1][2]

## نمایش واقعی صفحه، پس از آماده شدن کامل

برای جلوگیری از اشتباه گرفتن بارگذاری ناقص با نبودن داده، تا ظاهر شدن برگه حمل و نقل عمومی و تکمیل درخواست های آن صبر کردیم. یک برداشت اولیه دسکتاپ که هنوز آماده نبود، از مقایسه کنار گذاشته شد.

- دسکتاپ، ساعت **۱۱:۳۵:۱۵ به وقت تهران**: خط ۱۰۹۳، **۱۰۹ دقیقه**.
- مرورگر اندروید، ساعت **۱۱:۳۵:۲۴**: خط ۱۰۹۳، **۱۰۹ دقیقه**.
- مرورگر اندروید پس از بازخوانی معمول صفحه، ساعت **۱۱:۳۶:۳۴**: همان عدد **۱۰۹ دقیقه**؛ درخواست تازه شبکه هم ثبت شد.
- خطوط ۹۱، ۹۸ و ۴ در این مشاهدات نامشخص بودند.[3]

فاصله دو مشاهده اندروید ۷۰٫۰۰۷ ثانیه بود. در مشاهده زودتر همان مرورگر، عدد «۷ دقیقه» نیز دیده شد؛ آن عدد را نباید با آزمایش های بعدی یا تصویر گوشی کاربر که ساعت ۱۰:۳۹ را نشان می دهد، هم زمان فرض کرد. از این تفاوت، رابطه علت و معلولی با User-Agent نتیجه نمی گیریم.

اعداد بالا **گزارش نمایش خود نشان** هستند، نه تایید میدانی رسیدن اتوبوس. زمان اندازه گیری ارائه دهنده و دقت پیش بینی هنوز مشخص نشده است. نتیجه قبلی «نامشخص برای همه خطوط» مربوط به مشاهده های ساعت ۱۰:۱۱ و ۱۰:۱۲ بود و نباید به وضعیت دائمی نسخه وب تعبیر شود.

## لینک شهرداری

نشانی ارسالی، بدون تغییر، آزمایش شد:

```text
https://map.mashhad.ir/fa
```

نتیجه ثبت شده در `system-dns.json` و `network-stages.json`:

- DNS این بار به `5.252.219.39` پاسخ داد.
- اتصال TCP مستقیم به درگاه ۴۴۳ برقرار شد، اما مذاکره TLS در مهلت آزمون کامل نشد؛ پاسخ HTTP دریافت نشد.
- با پروکسی موجود، CONNECT موفق بود ولی TLS مقصد باز هم کامل نشد.
- کنترل سلامت همان پروکسی با یک نشانی مستقل HTTP 200 گرفت.
- نشانی HTTP نیز جداگانه آزمایش شد و در مهلت آزمون هیچ بایتی برنگرداند.
- تلاش مرورگر در ابزار پیمایش متوقف شد و برداشت بعدی `about:blank` بود؛ آن را محتوای سایت یا خطای احراز هویت سایت حساب نکردیم.

این شواهد، خرابی قطعی سایت یا مسدود بودن جغرافیایی را ثابت نمی کنند. محتوای سامانه و API اتوبوس از این میزبان دریافت نشد. تغییر صرف هدر HTTP، مشکل مشاهده شده پیش از تکمیل TLS را حل نمی کند.

## مسیر پیشنهادی

- نشان را فعلاً مسیر اصلی بررسی فنی نگه داریم؛ امکان مشاهده عدد از وب اثبات شد.
- برای اتصال محصولی، قرارداد و قالب پاسخ مجاز، شناسه خط و جهت، زمان تولید پیش بینی و رفتار داده نامشخص مشخص شوند؛ نه اینکه صرف HTTP 200 موفقیت اتصال حساب شود.
- دسترسی شهرداری از اینترنت گوشی کاربر بررسی شود. اگر باز می شود، تصویر بخش اتوبوس یا لینک عمومی یک ایستگاه می تواند منبع بعدی بررسی باشد؛ نیازی به ارسال توکن، کوکی یا اطلاعات ورود نیست.

شواهد خام محدود و نتیجه ساخت یافته در فایل های JSON همین پوشه نگهداری شده اند. هیچ رمزگشای اختصاصی، برداشت انبوه یا اتصال آنلاین به محصول ساخته نشد.
